# Requests vs HTTPX (requests 2.34.2, httpx 0.28.1)

Evidence packet for https://scrapingant.com/blog/requests-vs-httpx

## What this demonstrates
Every snippet and every timing in the article, run against one local server (`server.py`: hypercorn, plain HTTP/1.1 on 127.0.0.1:8080 and TLS with ALPN `h2` on localhost:8443 with a self-signed certificate generated by `run.sh`). The server counts TCP connections and requests per path (`/stats`), so each table shows how many connections a client actually opened.

- `01_basics.py` — the same GET/POST with both; object differences; form/json/raw bodies; query-parameter edge cases
- `02_defaults.py` — redirects (followed by default in requests, not in httpx) and timeouts (none vs 5 s)
- `03_pooling.py` — 300 sequential requests with and without a `Session`/`Client`, plain and TLS; the cost of building an SSL context per `httpx.get()` call
- `04_concurrency.py` — 200 requests with a 50 ms server delay: sequential, 20 threads, `AsyncClient` with a semaphore, with default limits, with sized limits; urllib3's "pool is full" warning
- `05_http2.py` — negotiated protocol, `http2=True` without `h2`, 200 concurrent requests over HTTP/1.1 vs HTTP/2, sequential requests over both, one public HTTP/2 server
- `06_streaming.py` — a 50 MiB body buffered and streamed, wall time and peak RSS per process
- `07_errors.py` — exception classes side by side; what `retries` means in each library (server request counter)
- `08_migration.py` — the errors and deprecation warnings a requests codebase hits on httpx 0.28
- `09_httpx1_preview.py` — installs httpx 1.0.dev6 into `generated/` and runs the 0.28 calls against it
- `10_popularity.py` — 30-day PyPI download ranks (hugovk/top-pypi-packages) → `expected_output/popularity.json`
- `11_scrapingant.py` — the same API call with both clients; runs only with `SCRAPINGANT_API_KEY`, otherwise prints "skipped"

## Run
```bash
python -m venv .venv && . .venv/bin/activate   # Python 3.12
pip install -r requirements.txt
./run.sh
```
Needs `openssl` on PATH (certificate generation) and outbound HTTPS for cases 05 (one public request), 09 (pip install) and 10.

## Limitations
- Seconds depend on the machine (recorded on an Apple Silicon laptop, loopback); the ratios and the connection counts are the claims.
- Loopback has no real latency, so connection setup and TLS handshakes dominate; on a remote server the sequential rows move closer together and the concurrency rows further apart.
- `ru_maxrss` is bytes on macOS and KiB on Linux; `06_streaming.py` converts both to MiB.
