# What Is Web Scraping? From an HTML Page to JSON

Evidence packet for https://scrapingant.com/blog/what-is-web-scraping

## What this demonstrates

Read an owned synthetic HTML catalog, select product cards with Beautiful Soup,
validate required fields, and serialize them to JSON. Compare the output with
an independently authored oracle. The fixtures are teaching data, not retailer
offers; the displayed prices are strings, not inferred currencies or numbers.
No API key, browser, network target or paid service is used.

## Run

From this directory, with Python 3.14.6 (the recorded version):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
./run.sh
```

Dependency installation may need network access; the example itself is offline.
The original run used an isolated virtual environment in `/private/tmp` and
`PYTHON=/private/tmp/what-is-web-scraping-venv/bin/python ./run.sh`.
`PYTHON` can select an already prepared interpreter. Nothing installs globally.

Run only the extractor:

```bash
python extract.py fixtures/catalog.html
```

Its stdout is captured in `expected_output/catalog.json`. Inspect a failure:

```bash
python extract.py fixtures/missing-price.html
```

This command must exit 1 and print `ERROR: p2: missing price` to stderr. It emits
no JSON, even though the earlier product has all fields. The verification runner
checks this expected failure and continues; unexpected failures stop the run.

## Files

- `extract.py`: complete runnable extractor and CLI, with explicit `html.parser`.
- `fixtures/catalog.html`: three synthetic product cards, including Unicode and an HTML entity.
- `fixtures/expected-records.json`: independent manually authored expected records; never regenerated by the extractor or runner.
- `fixtures/missing-price.html`: a valid first product followed by one missing price.
- `fixtures/javascript-only.html`: a product card exists only in script text; parsing does not execute that script.
- `verify.py`: CLI/output checks plus blank-price, missing-ID/title and duplicate-ID controls.
- `run.sh`: runs verification and captures its transcript with `pipefail`.
- `expected_output/`: actual JSON, error captures, verification transcript, versions and fixture hashes.
- `evidence.yaml`: dated source and measurement manifest.

## Denominators and limits

There are three expected records with three fields each; compare all nine values
and exact record/key structure to the independent oracle. The eight verification
checks count one catalog comparison, one text representation observation, two
CLI negative controls and four function-level negative controls. The text
observation is included in the catalog oracle comparison, not a separate sample.
These counts describe this fixture only, not accuracy on websites generally.

The extractor assumes this markup. A site with different selectors, multiple
prices or page navigation needs different rules. It does not fetch URLs, crawl,
execute JavaScript, validate retail price semantics, or access a site's database.
The script fixture shows the parser's boundary; no browser rendering was tested.
No screenshots, personal data, external content copies or legal advice are used.
