# Independent methodology and harness review

Reviewed September 22, 2026, initially during execution and again after the complete matrix and replacement runs. Scope: README, Python and Node probes, shared extractor, local fixture, orchestrator, summarizer, package/repository metadata, raw captures, representative screenshots, and final report assertions. No browsers were launched and no capture or implementation files were changed by this review.

The design supports a dated, exploratory comparison of the displayed BrowserScan categories and Sannysoft checks under these specific configurations. It does not support a universal detection-evasion ranking or causal attribution to individual patches.

## Final review outcome

Independent aggregation from an isolated temporary copy of the final summarizer passed `--require-complete` and reproduced canonical `summary.json` exactly. The packet contains 28 canonical runs, 28 BrowserScan observations, 14 Sannysoft observations, and 28 local-fixture captures. All compared six-/ten-second verdict/category states agree, and no Sannysoft warning states occur. Every BrowserScan table cell and named Sannysoft failure in `report.md` matches the saved observations. The local-fixture webdriver/platform assertions and recorded host/runtime/browser versions also match. The two invalid Node pilots are present under `pilot-errors/` and excluded from canonical aggregation.

The method and numerical report are suitable as bounded research evidence, with the interpretation limits below. The remaining process-cleanup robustness finding does not affect this completed matrix, which passed strict coverage. Recommendations are practical choices for the tested configurations, not statistically estimated superiority or production-access guarantees.

**Screenshot limitation:** the original `extra-stealth-headless-1-browserscan.png` and `python-stealth-headless-1-browserscan.png` captures have result content shifted beyond the right viewport edge. The reviewer inspected both and could not visually verify their verdict/category text from those images. Their validated DOM snapshots remain the evidence for their reported results. The report must disclose this distinction rather than imply every linked screenshot visually verifies the result; any later layout-repair capture is supplemental and must not silently replace an original observation.

**Supplemental layout audit:** three additional headless BrowserScan visits (two Node stealth, one Python stealth) are retained separately in `layout-audit/` and do not change the canonical 28-observation count. The layout records show a 4000-pixel-wide body/document with a 1440-pixel viewport and result content outside that viewport, explaining the clipping. Independent inspection of `layout-audit/extra-stealth-headless-full.png` shows `Normal` and four white labels, matching its JSON. `layout-audit/python-stealth-headless-full.png` shows `Robot` and red `Navigator`, also matching its JSON. The separate `layout-audit/post-capture-check/extra-stealth-headless-full.png` again shows `Normal`; its recorded before-/after-screenshot DOM states both remain `Normal` with four white labels. An initially suspected Node image/DOM contradiction was a multi-image viewing mixup, not a measured detector-state change. These audit artifacts provide no evidence of screenshot-induced detection. They corroborate the configurations in additional visits but are not screenshots of the original canonical visits.

## Initial findings and resolution status

1. **Resolved P1 — Validate the Sannysoft schema before interpreting an empty failure list.** In the initial `scripts/summarize.py`, `states()` silently excluded rows whose second cell had an unfamiliar CSS class. A populated page containing six or more unclassified rows satisfied the probe's row-count assertion, but could produce `classified_rows: 0`, `failed: []`, and `stable_6_to_10s: true`. The revised summarizer requires the expected unique named check set and exactly one recognized state per check. The reviewed valid captures each contained 31 classified checks; no incorrect saved success result was identified.

2. **Resolved P1 — Check expected matrix coverage explicitly.** The initial summarizer only read existing files and pages, allowing missing observations to disappear from a comparison. The revised `--require-complete` validates all 28 approach × mode × repetition keys, 28 successful BrowserScan observations, and 14 successful Sannysoft observations. Repetition 2 intentionally has no Sannysoft capture and is explicitly reported as “not repeated.” Archived pilot artifacts must remain outside the canonical set.

3. **Resolved P2 — Harden semantic validation of BrowserScan observations.** The initial label/color validation did not constrain verdict text, HTTP status, or final URL. The revised summarizer validates a unique four-label set, recognized colors and verdicts (`Normal` or `Robot`), the expected site/page, and HTTP 200. Strict mode also checks screenshot presence. No mismatch was found in the reviewed snapshots.

4. **P2 — Preserve explicit failure records for non-timeout process failures.** `run_matrix.py` writes a placeholder only for its primary 180-second timeout path. A child that exits without writing JSON can leave an absent run, and `child.wait(timeout=10)` after SIGTERM can itself raise before the placeholder is written. Node also awaits `browser.close()` before writing its result, so a close failure can lose already captured observations. These paths do not invalidate saved good observations, but they require the coverage audit above; future harness hardening should always record the process outcome and persist observations even when cleanup fails.

## Extraction checks

- The shared extractor reads result DOM rather than inferring detector output from local browser properties. Python evaluates the callback string through its API; the corrected Node adapter compiles the owned local callback and passes a function. The two known Node pilot files, `extra-stealth-headless-1` and `rebrowser-headless-1`, contain missing snapshots caused by the earlier invocation bug. They are invalid harness trials, not library failures, and were archived and replaced.
- The Chrome headless BrowserScan screenshot visibly shows `Robot`, red `Webdriver` and `User-Agent`, and white `CDP` and `Navigator`. The Camoufox headless screenshot visibly shows `Normal` and four white labels. Both agree with the retained DOM extraction. The Python stealth Sannysoft screenshot's visible first-table checks agree with their `passed` classes. Screenshots are viewport captures, so lower Sannysoft checks are supported by raw DOM rows rather than visible screenshot coverage.
- Sannysoft has ordinary descriptive rows after its classified checks. Excluding those descriptive rows is correct; the revised summarizer rejects an unexpected classified-check schema.
- Stability is limited to the two sampled instants and the compared verdict/category states. It does not establish that tests finished permanently, that intermediate states were unchanged, or that the observation did not affect detection. This limitation is appropriately acknowledged in the README.

## Interpretation constraints for the report

- Separate headless and headed findings. Compare each Chromium approach to its Chrome control, while retaining exact framework and browser versions. Rebrowser 1.52.0 against Chrome 153 is a different framework-version configuration from Playwright/Patchright 1.63.0; present results for that tested combination.
- Camoufox 152.0.4-beta.30 versus the Firefox 153 control changes build and fingerprint behavior together. It is useful context but not an isolated test of a patch. Chromium-oriented Sannysoft checks such as `Chrome (New)` are not a fair cross-engine aggregate score.
- The ordinary Chrome control already has an unflagged BrowserScan CDP category. Therefore the matrix cannot demonstrate that a special library defeated a working CDP-positive control. “CDP was not flagged” is supported; “CDP bypass was proven” is not.
- The Python stealth fixture records a Mac user agent with `platform: Win32`, while BrowserScan flags `Navigator`. This supports reporting both observations and a possible consistency issue; it does not identify BrowserScan's exact decision rule or prove causality.
- Package defaults may deliberately modify platform, language, hardware concurrency, WebGL, and other properties. The comparison tests these defaults with the documented viewport/OS/build constraints. It does not establish the best achievable configuration for each library. Camoufox fingerprint generation also varies between launches; two repetitions are too few for rate estimates.
- Report BrowserScan's literal verdict and named red categories, and Sannysoft's named failed/warning checks. An empty valid failure list means only that no captured check was marked failed. Do not translate it into “undetectable,” a target-site access rate, CAPTCHA success, or performance.
- Reversing approach order on repetition 2 is a modest order-bias mitigation, not randomization. The repaired Node pilot replacements occurred outside the intended first-pass order; the report discloses that deviation and the invalid pilots are retained separately.
- Repository head revisions describe repository state at inspection, not necessarily the exact source commit packaged in each registry release. Keep package pins/locks as execution identity, and avoid treating an old default-branch timestamp alone as proof of abandonment.

## Reuse conditions

Retain original observations and pilot provenance, keep strict schema/coverage validation, and disclose screenshot limitations and any supplemental captures. The completed matrix and replacement runs satisfy the numerical/schema checks, with no final errors or unstable states. No additional live detector run is required merely to validate saved JSON. Reusing these results for a future article still requires the project's article-specific evidence and publication workflow.
